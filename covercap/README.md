# COVERCAP — сайт крышек KISS

Продающий лендинг по ТЗ «COVERCAP × KISS, v1»: каталог из двух позиций, запрос расчёта, приём заявок с сохранением в базу, админка для заявок и цен, Яндекс Метрика по согласию. Корзины, онлайн-оплаты и личного кабинета нет.

## Состав

| Путь | Что это |
|---|---|
| `index.html` | Главная: блоки 01–10 из ТЗ. Тексты индексируемые, в HTML. |
| `content.json` | **Единый источник** цен, контактов, реквизитов, матрицы «размер × цвет», номера Метрики. Правится через админку. |
| `assets/` | Стили, скрипт, шрифты (Playfair Display + Manrope, лицензия OFL, хранятся у себя, без Google Fonts), фото в WebP. |
| `api/lead.php` | Приём заявки: проверка → запись в SQLite → ответ с `lead_id` → уведомление на почту / в Telegram. |
| `admin/` | Заявки и статусы, отчёт «источник → оплата», выгрузки, редактор цен и контента. |
| `privacy/`, `consent/` | **Черновики** политики и согласия: поля `[…]` заполняет заказчик, текст утверждает юрист. |
| `thanks/`, `404.html` | Служебные страницы (закрыты от индексации). |
| `private/` | `config.php` с паролями и ключами (не коммитится). Образец: `config.sample.php`. |
| `data/` | База заявок, резервная очередь, бэкапы `content.json` (не коммитится, закрыта от веба). |

## Хостинг

Нужен обычный хостинг с **PHP 7.4+ (pdo_sqlite, mbstring)** и Apache, сервер в РФ (Рег.ру, Beget, Timeweb и т.п.). GitHub Pages для боевой версии не подходит: там не работает приём заявок.

1. Залить содержимое папки `covercap/` в корень домена covercap.ru.
2. Скопировать `private/config.sample.php` в `private/config.php` и заполнить: почту для уведомлений, соль, пользователей.
   Хэш пароля: `php -r 'echo password_hash("пароль", PASSWORD_DEFAULT), PHP_EOL;'`
3. Дать веб-серверу право записи в `data/` и в файл `content.json`.
4. Проверить, что `https://covercap.ru/data/leads.sqlite` и `https://covercap.ru/private/config.php` отдают 403.
5. После выпуска SSL включить редирект на HTTPS в `.htaccess`.

Локально: `php -S 127.0.0.1:8090 -t covercap` и открыть http://127.0.0.1:8090/.

## Как устроен приём заявок

- В форме два поля: имя и телефон, плюс отдельная галочка согласия. Выбранный в каталоге размер и цвет передаётся скрытыми полями.
- Каждое открытие формы получает `submission_id`. Двойной клик или повторная отправка возвращают **тот же** `lead_id`, дубль не создаётся.
- «Заявка получена» показывается только после ответа сервера о сохранении. При ошибке данные остаются в форме.
- Если база недоступна, заявка пишется в резервную очередь `data/queue.jsonl` и переносится в базу при следующем обращении (без дублей).
- Защита от спама: скрытое поле-ловушка и лимит 5 заявок за 10 минут с одного IP (IP хранится только как хэш).
- В Telegram уходит только номер заявки и ссылка в админку. Персональные данные — только в базе и в письме на рабочую почту.
- Без JavaScript форма тоже работает: обычный POST и переход на `/thanks/`.

## Админка (`/admin/`)

- **Заявки**: фильтр по статусам *Новая → Контакт установлен → Квалифицирована → Расчёт отправлен → Согласована → Оплачена → Отгружена*, отдельно *Отказ* (причина обязательна). В карточке: ответственный, номер заказа, суммы оплат и возвратов, повторная отправка уведомления.
- **Отчёт**: источник → заявки → квалифицированные → расчёты → оплаченные → сумма за вычетом возвратов, причины отказов, за 7 / 30 дней / всё время.
- **Выгрузки**: все заявки в CSV (для Excel), офлайн-конверсии `qualified_lead` / `order_paid` для Метрики (`ClientId,Target,DateTime,Price,Currency`). Строки детерминированы, поэтому повторная загрузка оплату не задваивает.
- **Цены и контент** (только роль `admin`): цены Д80/Д90, переключатель «Публиковать», дата актуальности, НДС, условие объёма, минимальный заказ, доставка; матрица цветов (*доступно / уточняется / скрыто*); контакты, реквизиты, ссылка на PDF КП, номер Метрики, пометка «временное фото». Перед каждым сохранением делается бэкап.

Пока нет отметки «Публиковать» **и** даты актуальности, сайт везде показывает «Цена по запросу». Числа 3,8 / 3,9 ₽ из КП в сайт не внесены: в ТЗ они не утверждены.

## Аналитика

Метрика подключается только после «Разрешить» в баннере cookies и при заполненном номере счётчика. Вебвизор выключен, у полей формы стоит `ym-disable-keys`. Цели (`reachGoal`):

| Цель | Когда |
|---|---|
| `quote_open` | открыта форма, параметр `placement`: header / hero / catalog / price / footer / mobile_bar / repeat |
| `variant_select` | выбран размер или цвет (в каталоге или в форме) |
| `lead_success` | сервер подтвердил сохранение; один раз на `lead_id` |
| `lead_error` | ошибка: только код, без полей |
| `contact_click` | клик по телефону, почте или Instagram |
| `proposal_download` | клик по PDF КП |
| `qualified_lead`, `order_paid` | офлайн-конверсии из админки |

В заявке сохраняются UTM-метки, страница входа, реферер (без query), кнопка, `yclid` и ClientID Метрики (если пользователь разрешил cookies). Первый источник запоминается только при согласии, иначе «Не определён».

## Запуск: что сделать до публикации

- [ ] Убрать `<meta name="robots" content="noindex, nofollow">` из `index.html` (сейчас прототип закрыт от индексации).
- [ ] Заменить временные фото из КП оригинальными предметными снимками (каждый цвет: вид сверху, под углом, на стакане; 1600–2400 px), затем снять галочку «временное фото».
- [ ] Максим: подтвердить матрицу «размер × цвет» (сейчас доступен чёрный, белый и красный — «уточняется»), отпускные цены, НДС, минимальный заказ, доставку.
- [ ] Внести телефон, почту, часы работы, реквизиты продавца.
- [ ] Юрист: утвердить `privacy/` и `consent/`, убрать плашку «черновик» и `noindex` с этих страниц, обновить `consent_version`.
- [ ] Номер счётчика Метрики, цели в интерфейсе Метрики с теми же названиями.
- [ ] Прогнать приёмку из ТЗ (раздел 11): 20 положительных и 5 негативных заявок. Сбой хранилища имитируется через `'fail_test' => true` (резервная очередь) или `'total'` (ошибка) в `private/config.php`.
- [ ] Добавить Product/Organization в разметку только после подтверждения данных.

## Версии дизайна

- **Текущая (v2)** — `index.html` и `assets/` в корне папки: сетка с линиями, шрифты Unbounded и Onest, цвета крышки.
- **Первая (v1)** — архив в `v1/` (открывается по адресу `/covercap/v1/`). Использует те же `content.json`, приём заявок и документы.

Откат на v1: скопировать `v1/index.html` и `v1/assets/` в корень папки и вернуть в `index.html` пути без `../` (форма → `api/lead.php`, документы → `privacy/`, `consent/`, иконка → `favicon.svg`), а в `assets/covercap.js` — `fetch('content.json'`.
